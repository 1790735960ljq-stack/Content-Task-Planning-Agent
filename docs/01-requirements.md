# 需求

## 用户和目标

用户是运营人员。目标是在预算和截止时间内完成一份内容活动方案。

## 输入和材料

输入是主题、预算、截止时间。材料是合成素材、工具费用和耗时表，放在 [data/assets.json](../data/assets.json) 和 [data/cost_table.json](../data/cost_table.json)。费用单位是模拟单位。

提供四个工具：素材检索、脚本生成、成本估算、方案保存。脚本由本地模板根据素材生成，不额外调用模型。

## 范围

本次做 CLI 和可重复的测试、运行记录。不做界面、线上部署、多 Agent，也不做失败步骤的跨进程续跑。续跑是加分项，记在复盘里。

## 成功标准

一次运行结束时给出：

- 任务计划：检索、生成脚本、估算、保存四个阶段及每次尝试
- 步骤状态：只追加，失败不会被后来的成功改写
- 工具结果
- 费用合计：只计入已保存方案
- 已保存方案，或未完成原因和缺口

必须覆盖：正常完成、缺预算或截止时间、工具失败、预算超限、重复执行。

参考数字：预算 10 时，标准方案估算 12，精简方案估算 8。模型看到超预算后应改选精简方案，再估算并保存。两种方案都不可行时不保存，并给出缺口。

动态决策要能看出：模型根据成本超限、工具错误或部分成功调整下一步、选择替代方案或停止，并保留已成功步骤的结果。固定分支、自动重试或预设决策日志不能代替这个循环。
